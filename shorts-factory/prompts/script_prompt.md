## 構成ルール（厳守）

- 構成: 強いフック（冒頭1〜2キュー）→ 本編（具体的な手順やコツ。数字・改善前/改善後を入れる）→ まとめ（1キュー。「保存して試してみてください」等の汎用的な締め）
- 冒頭フックはショート動画向けに強める。1キュー目は必ず「損していること」「見落としている失敗」「意外な事実」のどれかで始め、視聴者が続きを見たくなる問いかけにする。
- 2キュー目までに「でも、やり方は簡単です」「原因はここです」「見るべきポイントは三つです」のように本編への引きを入れる。
- 冒頭で避ける表現: 「今日は〜を紹介します」「〜について解説します」「便利です」「おすすめです」など、説明開始だけで終わる弱い入り。
- 冒頭で使いやすい型: 「まだ〜していませんか？」「それ、〜が原因かもしれません」「〜で損していませんか？」「実は〜だけで変わります」
- キュー数: 10〜14個。1キュー = 画面に出る字幕1枚 = 読み上げ1文
- 話し言葉で、です・ます調。1キューは短く歯切れよく
- 全キューの tts_text 合計は 280〜400文字（ひらがな換算）。これが30〜60秒の動画になります
- ChatGPTだけを万能扱いしない。Claude、Gemini、Perplexity、NotebookLM、Canva、Gamma、Zapier、Make、n8n など、テーマに合うAIツール全般を扱ってよい
- ツール紹介だけで終わらせず、必ず「選定基準」「業務手順」「人間チェック」「社内定着」「効果検証」のどれかを入れる
- AI専門家として見えるように、単なる小技ではなく、業務設計や導入判断の視点を入れる
- 誇大表現・断定的な効果保証・他社誹謗は禁止。実在しない機能をでっち上げない

## 各キューのフィールド

- `display`: 字幕表示用。1〜2行の配列。**1行は最大13文字**（全角換算）。英字・%記号は原則使わず、読み上げやすい日本語にする（例: Before/After→改善前/改善後、15%→15パーセント）。ただし英語のツール名・サービス名・一般的な英字略語は必ず英字表記で表示し、カタカナ表記にしない（例: `AI` / `ChatGPT` / `Claude` / `Gemini` / `Perplexity` / `NotebookLM` / `Canva` / `Gamma` / `Zapier` / `Make` / `n8n` / `OpenAI` / `Figma` / `Google Drive` / `Notion` / `Slack` / `Zoom` / `Teams` / `Excel` / `PowerPoint` / `PDF` / `API` / `URL` / `CSV` / `KPI` / `CRM` / `SNS` / `LLM` / `DX`）
- `tts_text`: 読み上げ用の文。displayと同内容。ChatGPT以外の英字・%記号は避け、カタカナまたは日本語に直す（例: ABテスト→エービーテスト）
- `reading_kana`: tts_text の正確な読みを**全てカタカナ**で。英語用語もカタカナ化（ChatGPT→チャットジーピーティー）。数字も読みで（3分→サンプン）
- `emphasis`: 特に強調したいキューなら true（全体の2〜3個まで）。冒頭1キュー目は必ず true にする

## 重複禁止ルール（厳守）

- 上の直近動画と、同じ業務テーマ・同じ課題・同じ解決手順に見える台本は禁止。
- 「型化」「テンプレ化」「標準化」「仕組み化」「パターン化」「共有して再利用」の切り口は、直近で何度も使っているため原則使わない。
- テーマが違っても、結論が「型を作る」「テンプレ化する」「チームで共有する」だけになる場合は不合格。
- 今回のテーマ固有の対象物・判断基準・具体手順を入れ、過去動画と別物に見える内容にする。
