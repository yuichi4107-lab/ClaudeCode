# Internal Tool Security Review

## 使う場面

社内ツールの実装後、リリース前、外部連携追加前、認証・権限・個人情報・ログ出力に関わる変更時に使う。

## 基本方針

社内ネットワーク内のツールでも、秘密情報漏洩、権限不備、ログ漏洩、誤操作、外部送信は起こり得る。レビューでは「動くか」だけでなく「漏れないか」「壊さないか」「権限外操作できないか」を確認する。

## 確認手順

1. 扱うデータを分類する。
   - 公開情報
   - 社内情報
   - 機密情報
   - 個人情報
   - 顧客情報
   - 認証情報

2. 秘密情報を確認する。
   - パスワード、APIキー、トークン、秘密鍵をコードに直書きしていない
   - `.env` や認証ファイルをGit管理していない
   - `.env.example` はダミー値または空欄になっている
   - ログやエラー画面に秘密情報が出ない

3. 認証・権限を確認する。
   - ログインが必要な画面・APIに認証がある
   - 権限チェックがサーバー側にある
   - 管理者操作を一般ユーザーが実行できない
   - セッション、Cookie、CSRF対策が用途に合っている

4. 入力値を確認する。
   - SQLインジェクション対策
   - コマンドインジェクション対策
   - XSS対策
   - ファイルアップロードの拡張子、サイズ、保存先制限
   - SSRFにつながる任意URL取得の制限

5. ログ・エクスポートを確認する。
   - 個人情報や秘密情報をそのままログに出していない
   - CSVやレポートに不要な個人情報が含まれない
   - 大量ログやDB内容をターミナルに表示しない
   - ログ保持期間とアクセス権が妥当

6. 外部通信を確認する。
   - 外部APIやクラウドへ送信するデータが明確
   - 外部送信に承認がある
   - TLS検証を無効化していない
   - タイムアウトとエラー処理がある

7. 破壊的操作を確認する。
   - 削除、一般更新、移行に確認手順がある
   - バックアップまたはロールバック方法がある
   - 本番DBや共有スヌレヸを誤って変更ずない

8. 依存関係を確認する。
   - 不要な依存パッケージを追加していない
   - バージョンが固定されている
   - 既知の脆弱性やライセンス上の問題がない

## 判定

重大度を以下で分類する。

- Critical: リリース禁止。秘密情報漏洩、権限バイパス、本番破壈リスク。
- High: 修正必須。個人情報漏洩、外部送信不備、重大な入力検証不足。
- Medium: 修正推奨。運用上の事故や限定的な情報漏洩につながる。
- Low: 改善推奨。保守性や説明不足。

## 出力形式

```md
# セキュリティレビュー

## 結論

## Critical

## High

## Medium

## Low

## 確認できた項目

## 確認できなかった項目

## リリース可否
```

## 禁止事項

- 「社内だから問題ない」として指摘を省略する
- 秘密情報をそのまま回答やログに表示する
- 本番操作や削除操作を承認なしで実行する
- 認証・権限の不備を軽微扱いにする
- 外部送信の有無を確認せず安全判定する
