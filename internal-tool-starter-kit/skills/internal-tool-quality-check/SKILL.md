# Internal Tool Quality Check

## 使う場面

社内ツールの実装後、修正後、リリース前、研修課題の提出物確認時に使う。

## 基本方針

品質チェックは「動いたか」だけではなく、要件、セキュリティ、保守性、運用性を含めて確認する。100点満点で採点し、85点以上を合格とする。

## 確認手順

1. 要件定義を確認する。
   - ゴールに合っている
   - スコープ外の変更をしていない
   - 完了条件を満たしている
   - 承認が必要な変更を勝手に進めていない

2. 差分を確認する。
   - 変更ファイルが妥当
   - 無関係な変更がない
   - 既存のユーザー変更を戻していない
   - 秘密情報や巨大ファイルを追加していない

3. 動作を確認する。
   - 主要機能が動く
   - エラー時の表示が安全
   - 境界値や空データを扱える
   - 操作ミスで重大な破壊が起きにくい

4. テストを確認する。
   - 既存テストが通る
   - 変更内容に見合うテストがある
   - テストできなかった場合は理由を明記する
   - 長いログは200行以内に抑える

5. セキュリティを確認する。
   - 秘密情報が露出しない
   - 権限チェックがある
   - 入力検証がある
   - 外部通信が必要最小限
   - ログに個人情報や認証情報が出ない

6. 保守性を確認する。
   - 既存設計に合っている
   - 不要な抽象化がない
   - 命名が分かりやすい
   - 設定値がコードに埋め込まれていない

7. 運用性を確認する。
   - 起動方法が明確
   - 障害時の確認箇所が分かる
   - ロールバックまたは復旧方法がある
   - 本番反映前に人間が確認すべき点が明確

## 採点基準

- 要件適合: 25点
- 正常動作・テスト: 20点
- セキュリティ・データ保護: 20点
- 保守性: 15点
- 運用性: 10点
- ドキュメント・引き継ぎ: 10点

85点以上で合格。85点未満は不合格として、改善指示を出す。

## 出力形式

```md
# 品質チェック

## スコア

XX / 100

## 判定

PASS / FAIL

## 主な確認結果

## 問題点

## 修正必須

## 修正推奨

## 実行したテスト

## 実行できなかったテスト

## 残リスク
```

## 禁止事項

- テスト未実行なのに「問題なし」とする
- セキュリティ確認を省略する
- 85点未満を合格扱いにする
- ログや秘密情報を大量表示する
- 残リスクを隠して完了報告する
