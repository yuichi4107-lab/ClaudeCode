# 製造系中小企業向け「Notion × AI」導入提案プラン

対象: 部品メーカー・町工場など、従業員 10〜100 名規模の製造系中小企業
目的: Notion を「社内の情報ハブ」、AI を「入力・検索・文書作成の省力化エンジン」として組み合わせ、
属人化・紙文化・二重入力という中小製造業の構造的な課題を段階的に解消する提案の全体設計。

---

## 1. エグゼクティブサマリー

- **課題の本質**: 中小部品メーカーの現場は「紙・Excel・ホワイトボード・口頭」で回っており、
  情報が *探せない・残らない・引き継げない*。ベテラン退職による暗黙知の喪失が最大の経営リスク。
- **提案コンセプト**: 高価な基幹システム（ERP/生産管理パッケージ）を入れる前段として、
  Notion で「案件・図面・工程・品質・ノウハウ」を一元化し、AI で入力と検索の負荷を極小化する。
  月数万円から始められ、失敗してもダメージが小さい「軽量DX」。
- **勝ち筋**: ①図面の最新版管理とベテランノウハウのQ&A化という "痛みが強く即効性のあるテーマ" から入る
  ②効果を「探す時間・転記時間」で数値化して経営層に見せる ③PoC先行で小さく始めて広げる。
- **提供形態**: 3つのパッケージ（スモールスタート / スタンダード / AI連携開発）＋月次伴走支援。

## 2. ターゲットと課題仮説

### ターゲット像
- 従業員 10〜100 名の部品加工・金属加工・樹脂成形などの製造業
- 生産管理システム未導入、または Excel 台帳＋紙帳票が主体
- 経営層に事業承継・人手不足・ベテラン退職の危機感がある

### 典型的な業務とペイン（ヒアリングシートの骨子）

| # | 業務領域 | 現状のやり方 | 主なペイン |
|---|---|---|---|
| 1 | 受発注・案件管理 | 紙の注文書＋Excel台帳＋口頭 | 進捗が属人化、対応漏れ、二重入力 |
| 2 | 見積管理 | Excelテンプレをコピーして個別管理 | 過去見積が探せない、原価割れ発見が遅い |
| 3 | 図面・仕様書管理 | 共有フォルダ＋紙図面 | 最新版が不明、旧版加工事故、改訂履歴が追えない |
| 4 | 工程・進捗管理 | ホワイトボード＋口頭 | 現場外から進捗が見えない、記録が残らない |
| 5 | 設備保全 | 紙の点検表＋担当者の記憶 | 点検漏れ、修理履歴の散逸 |
| 6 | 品質・不適合管理 | 紙の検査成績書＋手書き台帳 | 再発防止に繋がらない、クレーム追跡が遅い |
| 7 | 在庫・購買 | Excel在庫表＋目視確認 | 欠品・過剰在庫、発注が属人的 |
| 8 | 技能伝承・マニュアル | 背中を見て覚えるOJT | ベテラン退職で暗黙知が消える |
| 9 | 日報・作業報告 | 紙日報→月末にExcel転記 | 転記の二度手間、リアルタイム性ゼロ |
| 10 | 顧客対応・クレーム | 個人の記憶＋メール埋没 | 履歴が担当者しか分からない、引継ぎ困難 |

## 3. 提案の基本コンセプト：3層アプローチ

```
┌───────────────────────────────────────────┐
│ 第3層  AI連携自動化（外部AI × Notion API）             │
│        OCR取込・メール自動分類・RAG検索ボット           │  難易度: 中〜高
├───────────────────────────────────────────┤
│ 第2層  Notion AI 活用                                  │
│        ノウハウQ&A・報告書ドラフト・翻訳・自動タグ付け   │  難易度: 低
├───────────────────────────────────────────┤
│ 第1層  Notion データベース基盤（情報の一元化）          │
│        案件・図面・工程・品質・設備・ノウハウのDB群      │  難易度: 低〜中
└───────────────────────────────────────────┘
```

- **第1層が土台**。AI は「入っているデータ」しか活用できないため、まず情報を Notion に集める設計が先。
- **第2層は追加開発ゼロ**。Notion AI の課金を有効化するだけで、蓄積したデータが「検索できる資産」に変わる。
- **第3層は PoC 先行**。精度と機密管理の設計が必要なため、小さく検証してから広げる。

## 4. 提案パッケージ（商品設計）

| パッケージ | 内容 | 期間・工数目安 | 想定対象 |
|---|---|---|---|
| **A. スモールスタート** | 図面管理＋ノウハウDB＋設備点検の3テーマに絞った Notion 構築、Notion AI の Q&A 運用設計、操作研修 | 1〜2ヶ月 / 5〜10人日 | 初回導入・PoC |
| **B. スタンダード** | A に加え、案件管理・工程進捗・日報・品質記録まで含むワークスペース全体設計、運用ルール策定、社内説明会 | 3〜5ヶ月 / 15〜30人日 | A で効果を確認した企業 |
| **C. AI連携開発** | 紙帳票OCR取込、メール自動分類、議事録自動化、社内Q&Aボット等を Zapier/Make または API 開発で個別構築 | 1〜6ヶ月 / 案件による（5〜60人日） | B 定着後の拡張 |
| **伴走支援（共通）** | 月次レビュー、利用状況分析、テンプレ改善、AI活用相談 | 月1〜2日の継続契約 | 全パッケージ |

**設計思想**: A→B→C の順に単価が上がる階段設計。A は「失注しにくい低価格・短納期」で入口を作り、
効果測定の数値を武器に B/C へアップセルする。

## 5. フェーズ別ロードマップ

### フェーズ1（1〜2ヶ月目）: 即効性が高く抵抗が少ないテーマ
1. **図面・仕様書管理DB** — 「最新版が分からない」痛みが強く、ファイルを上げるだけで効果を全員が実感
2. **技能・マニュアルDB** — 既存の紙マニュアル移行から始められ、写真・動画添付がすぐ評価される
3. **設備管理＋点検・保全記録DB** — 紙点検表をほぼそのまま置き換え可能
4. **Notion AI 有効化** — 蓄積が始まった時点でノウハウQ&A・翻訳・ドラフト作成を開放

### フェーズ2（3〜5ヶ月目）: 業務フローの中核
5. **案件管理DB** — 全社の情報ハブ。営業・生産管理の巻き込みが必要
6. **工程・進捗管理DB** — ホワイトボード代替。案件管理の定着後に接続
7. **日報DB** — 工程DBと連動させて二度手間を排除

### フェーズ3（6ヶ月目以降）: 分析・管理強化＋AI連携
8. **品質記録・不適合管理DB** — 「記録＝責任追及」と受け取られない心理的安全性の醸成後に
9. **在庫・購買DB群 / 見積管理DB / 顧客対応DB**
10. **外部AI連携（第3層）** — OCR取込・メール分類・Q&Aボット等を PoC → 本番展開

**定着の原則**
- 「入力する人」と「見る人」を分け、入力はボタン1つ・選ぶだけに簡素化
- 紙の完全廃止を急がず併用期間を設ける
- 現場ベテランを DB 設計の監修者に巻き込み、プロパティは「使われる項目」だけに絞る（項目過多は形骸化の最大要因）

## 6. Notion ワークスペース設計（概要）

### 6.1 データベース全体リレーション図

```
顧客マスタ
   │
   ├── 案件管理 ───┬── 見積管理
   │               ├── 図面・仕様書管理
   │               ├── 工程・進捗管理 ── 設備管理 ── 点検・保全記録
   │               │        │
   │               │        └── 入出庫記録 ── 資材マスタ ── 発注管理
   │               ├── 品質記録・不適合管理
   │               └── 日報
   │
   └── 顧客対応履歴 ── 品質記録・不適合管理（クレーム原因の紐付け）

技能・マニュアル ── 設備管理／工程種別／品質記録（トラブル事例）に横断リンク
```

### 6.2 主要DBの設計ポイント（抜粋）

| DB | 主要プロパティ | キーとなる仕掛け | 主なビュー |
|---|---|---|---|
| 案件管理 | 顧客(リレーション)、ステータス、納期、受注金額 | 数式「納期残日数」で遅延リスクを自動警告 | ステータス別ボード / 納期カレンダー |
| 図面・仕様書 | 品番、版数、最新版フラグ、ファイル、改訂理由、承認者 | 「最新版のみ」ビューを現場配布用に固定 | 品番グループ表 / サムネイルギャラリー |
| 工程・進捗 | 工程種別、担当設備(リレーション)、前工程(自己参照)、標準/実績時間 | 設備別グループ表でボトルネック可視化 | 進捗ボード / ガント / 設備負荷表 |
| 設備＋保全記録 | 種別、直近点検日(ロールアップ)、累計故障回数(ロールアップ) | 次回点検予定カレンダー＝点検リマインダー | 点検カレンダー / 異常抽出ボード |
| 品質・不適合 | 発生工程(リレーション)、原因分類、是正期限、損失額 | 原因分類別ボード＝パレート分析の元データ | 原因別ボード / クレーム抽出表 |
| 資材・在庫 | 現在庫数(入出庫ロールアップ)、発注点、発注要否(数式) | 「要発注のみ」ビュー＝日次発注チェックリスト | 要発注抽出表 / 入荷カレンダー |
| 技能・マニュアル | カテゴリ、関連設備、動画・写真、習得済み従業員 | 「習得済み従業員」でスキルマップを兼ねる | カテゴリ別ギャラリー / スキルマップ表 |
| 日報 | 関連工程(リレーション)、作業時間、トラブル有無 | 工程DB連動で転記レス化 | 日付カレンダー / トラブル抽出表 |

ロールアップ活用例: 案件→不適合件数、設備→故障回数、資材→現在庫数、顧客→累計クレーム件数。
Excel 台帳で手作業だった集計を Notion のリレーション＋ロールアップで自動化するのが第1層の核心。

## 7. AI 活用ユースケース

### 7.1 Notion AI 単体（第2層・追加開発不要）

| シーン | 使い方 | 効果 |
|---|---|---|
| ベテランノウハウへの自然言語Q&A | 熱処理条件・治具調整・過去トラブル対応を蓄積 →「〇〇材でクラックが出た時の対処は？」で該当ページを根拠付き回答 | 暗黙知を夜間・休日・退職後も参照可能に |
| クレーム／不適合報告書のドラフト | 現場が箇条書き入力 → AI が正式フォーマット（発生状況・原因・対策・再発防止）に整形 | 報告書の心理的ハードルを下げリードタイム短縮 |
| 英文引合い・海外メール対応 | 英文メールを貼付 → 日本語要約＋英語返信ドラフト | 英語要員なしで一次対応 |
| 手順書・QC工程表の多言語化 | 外国人技能実習生向けにベトナム語・中国語等へ翻訳 | 教育コスト削減、誤作業ロス低減 |
| 議事録要約とタスク抽出 | 生産・品質会議のメモを要約し決定事項をタスクDBへ | 「言った言わない」防止、フォロー漏れ削減 |
| DB自動入力（AI autofill） | ページ内容から分類タグ・要約列を自動生成 | 入力負荷の削減、検索性向上 |

### 7.2 外部 AI 連携（第3層・パッケージC）

| # | 施策 | 仕組み構成 | 難易度 |
|---|---|---|---|
| ① | Claude/ChatGPT + Notion API 自動要約・転記 | メール/PDF → AI で構造化 → Notion API で DB 登録（Zapier/Make で実装可） | 中 |
| ② | FAX・紙帳票 OCR → Notion 取込 | 複合機でPDF化 → クラウドOCR → AI で項目抽出（発注番号・品番・数量）→ DB 登録 | 高 |
| ③ | 議事録自動文字起こし → Notion 保存 | 音声認識 → Notion AI で要約・タスク抽出 → 議事録DBへ | 低〜中 |
| ④ | メール問い合わせの自動分類・起票 | Gmail/Outlook API → AI で「見積依頼/クレーム/納期照会」分類・優先度判定 → 自動起票＋通知 | 中〜高 |
| ⑤ | 図面・仕様書の社内AI検索（RAG） | PDF群をベクトル化 → Claude API で質問応答 | 高 |
| ⑥ | 社内Q&Aチャットボット（Slack/Teams連携） | Notion ナレッジを RAG 化しボットから応答 | 中〜高 |

難易度目安 — 低: 標準機能＋設定で数日 / 中: ノーコード連携で1〜4週間 / 高: カスタム開発で1〜3ヶ月。

## 9. 導入障壁と対策（中小製造業ならでは）

| 障壁 | 対策 |
|---|---|
| ITリテラシーのばらつき | 入力は「選ぶだけ・話すだけ」に簡素化。若手・事務職から小さく始めて成功体験を作る。マニュアルは動画・スクショ中心 |
| 現場にPCがない | タブレット1〜2台を「入力専用端末」として設置。音声入力・写真＋OCRで打鍵レス。まず事務所側から着手 |
| 図面の機密性（NDA・クラウド抵抗感） | **図面本体は社内サーバに置き、Notion にはメタ情報（品番・版数・工程・進捗）のみ**を載せる設計。Business 以上の権限管理・監査ログでアクセス最小化。外部AIへ図面画像を送らない運用ルールを明文化 |
| 経営層の投資判断材料が乏しい | 「探す時間・転記時間」を金額換算した年間削減試算を提示。PoC先行で Before/After を数値で見せる。中小企業庁のDX事例集等で「特殊なことではない」と伝える |
| ベテランの「ノウハウを取られる」抵抗 | ノウハウ提供を評価する仕組み（提供件数の見える化・手当）とセット。「引退後も会社に貢献し続けられる」前向きなフレーミング |
| 現場の「記録＝責任追及」警戒 | 品質記録DBはフェーズ3に回し、原因分類を「作業者要因」だけでなく設備・材料・図面要因まで用意して個人攻撃にしない設計 |

## 11. 営業アプローチ

### PoC先行型の提案ステップ
1. **無料〜低額の業務診断**（半日ヒアリング）: §2 のペイン一覧をヒアリングシートに使い、痛みの強い上位2テーマを特定
2. **パッケージA を PoC として提案**: 図面管理 or ノウハウQ&A のどちらか＋Notion AI で1〜2ヶ月
3. **効果報告会**: KPI（探す時間等）の Before/After を経営層へ提示
4. **パッケージB → C へ拡張契約**、伴走支援で継続関係を構築

### 社長向けトークサマリ
- 「まずは Notion AI だけで、ベテランの頭の中を "検索できる資産" に変えます。追加開発不要、月数万円から」
- 「図面そのものはクラウドに上げず、メタ情報だけ Notion で管理する設計なら、機密性とDXを両立できます」
- 「紙・FAX・メールの繰り返し作業は AI 連携で自動化できますが、小さく PoC してから広げます」
- 「効果は "探す時間・転記時間・クレーム対応速度" で数値化してお見せするので、投資判断がしやすくなります」
