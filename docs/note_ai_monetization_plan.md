## 1. 結論（30秒で読む）

**「予想を売る」のではなく「AIを作る過程を売る」。主軸は資産A（競馬AI）の開発実録教材、副軸は資産B（日本史×AIパイプライン）のワークフロー教材。**

- 現行モデルは **ROI -45.9%（413レース中5的中、FEATURE_IMPORTANCE_REPORT.md 実測値）**。改善目標ですら -20% で赤字前提。**予想を商品にすれば読者に損をさせる。この路線は封印する。**
- 一方、「競馬AIをゼロから作る過程」の教材化は実在市場がある（データサイエンス研究所の連載マガジン、Zenn電子書籍『競馬予想で始める機械学習』3,900円・ソースコード全公開モデル）。あなたには Phase 1〜7 の git 開発記録・実バックテストデータ・Claude Code スキル自作実績という **代替不可能な一次情報** がある。
- 目標: **90日で「note上に商品棚が完成し、累計手取り 3〜5万円（標準シナリオ）」**。金額より「外部流入つきの一次情報連載が回り、有料転換の実測データが取れている」状態を優先する。初期3ヶ月の実額として Baino Ryu の累計4,200円（★自己申告だが控えめな実額開示）を下限基準点に置く。
- 収益の主エンジンは有料記事（実用ノウハウ系の平均単価 **1,842円**＝note公式30万件分析）＋後期にメンバーシップ。note公式のAI学習対価還元プログラム（2025年8月本格開始、一次情報・検証記事が有利とされる）は副次収入として設計に織り込む。

## 3. 戦略の中核

### 3-1. ROI -45.9% を正面から扱う：予想は売らない、過程を売る

**判断: 予想販売はしない。** 理由は3つ。

1. **商品として成立しない（事実）**: nankan_v1 は 413レースで的中5、ROI -45.9%。CV精度79.9%は「2着以内に来るか」の分類精度であって馬券収支ではない。改善レポートの目標値ですら ROI -20% で、**買い続けた読者は確実に損をする**。読者が損をする商品は売らない——これは倫理であると同時に、返金要求・炎上・アカウント停止という事業リスクの回避でもある。
2. **市場の裏付け（リサーチ事実）**: 検証サイトの複数報告で「note予想家は総じて回収率100%割れ」。予想販売市場自体が「読者が負ける市場」であり、参入しても信頼を燃やして終わる。
3. **代替商品のほうが強い（実在モデル）**: データサイエンス研究所の連載マガジン、Zenn『競馬予想で始める機械学習〜完全版〜』3,900円は「AIをどう作るか」を売って成立している。**ROI -45.9%という失敗データそのものが、この市場では最強の教材になる。** 「精度79.9%でも馬券は当たらない」という体験は、これから競馬AIを作る全員が必ず踏む地雷であり、それを先に踏んで記録した者だけが書ける。

**予想販売を解禁する条件（将来）**: 十分な期間のフォワードテスト（バックテストではなく実運用記録）でROIがプラス圏に入り、かつ根拠データ・期間・条件を全文明示できる場合のみ再検討。それまでは「予想は無料でも出さない」（無料でも外れ続ければ信頼を毀損する）。

### 3-2. 資産配分：A主軸 70%・B副軸 30%

| | 資産A（競馬AI開発実録） | 資産B（日本史×AIパイプライン） |
|---|---|---|
| 実在する収益モデル | ◎ Zenn書籍3,900円・連載マガジンの先行例あり | △ 日本史ジャンルの収益実数は未確認（リサーチで得られず） |
| 競合密度 | ○ 「南関東×AI×開発過程」は空白の可能性が高い（**推測**。限られた検索に基づく） | ○ 「シニア向け×AI漫画パイプライン」は具体事例未発見（**推測**） |
| 一次情報の厚み | ◎ Phase 1〜7のgit履歴・実測ROI・40本のスクリプト | ○ スキル2本の実装・運用中のYouTubeチャンネル |
| 即金性 | ○ 教材需要が既に可視 | △ 市場検証から始める必要 |
| 外部導線 | △ これから作る | ◎ YouTubeチャンネルが既にある |

**判断: Aを主軸（初期60日の中心）、Bを副軸（61日目以降に1商品投入して市場テスト）。どちらも切らない。** Bを切らない理由: (1) YouTubeという既存導線を捨てるのは損失が大きい、(2) 「Claude Codeでワークフローをスキル化する」という技術は両資産に共通しており、発信テーマを「Claude Code実務活用の実録」で統一すれば2ジャンルが1つのアカウントで両立する。ただし初期からの二正面作戦は週5〜7hでは破綻するため、時間配分で明確に傾斜をつける。

### 3-3. あなたにしか書けない一次情報（棚卸し）

noteのアルゴリズムは読了率・外部流入・一次情報を優遇する（観測ベース）。還元プログラムも「AIが学習したがる一次情報＝体験談・検証記事」が有利とされる（事例#8）。以下は検索しても他に存在しない素材である。

1. **「CV精度79.9%なのにROI -45.9%」の実測データ一式**: 413レースのバックテスト、feature importance分析、改善仮説（相互作用項・条件フィルタ）。精度と収支が乖離するメカニズムの実例。
2. **Phase 1〜7 の開発記録（git log）**: 設計→実装→テスト→レビュー→トラブルシュート（Windows LightGBM DLL問題等）の全過程がコミットとして残っている。「後から整形した成功譚」ではない生ログ。
3. **未来リーク防止の設計判断**: FeatureBuilder の before_date 設計、TimeSeriesSplit、CalibratedClassifierCV の採用理由。競馬AI初心者が最初に間違える箇所。
4. **馬単確率の近似式 P(i→j) ≈ P_win(i)·P_place(j)/(1-P_win(i)) と2モデル構成**の設計プロセス。
5. **Win5システムの Kelly 基準資金管理・Optuna・Streamlit ダッシュボード**という別アーキテクチャとの比較。
6. **Claude Code スキルを2本自作した過程**: `japan-history-to-comicle-pipeline`（台本→30字分割→フリガナ→漫画CSVの4ステップ）と `history-loser-thumbnail`（栄光と転落の2幕構成をプロンプト化）。スキル自作の実務記事は需要に対して供給が薄い（**推測**）。
7. **60代以上向けコンテンツの設計制約**（1セリフ30字・カタカナフリガナ必須）という、シニア市場データ（YouTube利用率87〜90%、文字より動画を約2倍好む）に接続する実運用知見。
