# Notion 活用事例調査と導入提案
## 株式会社美建・日美株式会社（グループ）向け

- 調査日：2026年7月22日
- 調査方法：Notion公式カスタマーストーリー（notion.com/customers）、Notion正規販売代理店の導入事例、日本の実務者による一次情報を横断調査（世界33社の事例を収録）。並行して両社の公式サイトから事業内容・組織構成を分析。

## 1. エグゼクティブサマリー

美建・日美グループは「**少人数の本社が、多数の現場スタッフ・派遣スタッフ・登録者を管理する**」という共通構造を持っています。美建は本社16名で現場約216名（清掃190名・設備16名・保安10名）を、日美は正社員15名で派遣スタッフ約250名・登録者2万人超を支えています。

この構造では、**物件台帳・点検記録・マニュアル・案件情報・顧客対応履歴が紙とExcelに分散し、少人数の本社に情報が属人化する**ことが最大のリスクです。世界の事例を見ると、Notionはまさにこの「散在した情報の一元化」で最も効果を上げており、大阪ガスは月2,000時間の業務削減、トヨタは承認リードタイム1/3短縮、日本の小規模事業者でも解約率1/3化・更新作業3日→30分といった成果が出ています。

**提案の結論：**
1. **美建**：物件（現場）管理データベース＋業務マニュアルWikiから開始
2. **日美**：求人案件・企業CRM＋コンプライアンスWikiから開始
3. **グループ共通**：全社Wiki（規程・議事録・ノウハウ）を共通基盤に
4. まずは**無料プランで本社スタッフ数名からスモールスタート**し、3〜6か月で有料プラン（Business）へ段階移行

## 2. 御社の現状理解（公開情報より）

### 株式会社美建（総合ビルメンテナンス）
- 1972年創業、名古屋市中区。清掃・保安警備・設備管理・駐車場管理・補修工事の6事業
- 従業員 約232名。**本社スタッフ16名に対し現場スタッフ216名（約93%）**
- 顧客はビル・マンションのオーナー、管理組合、不動産管理会社。地域密着・常駐型モデル
- 想定される業務課題：物件ごとの契約・作業仕様の管理、法定点検の証跡管理、有資格者の配置管理、補修工事の見積〜施工進捗管理、クレーム・トラブル対応履歴の蓄積

### 日美株式会社（人材派遣・職業紹介）
- 1984年設立。人材派遣／紹介予定派遣／人材紹介／アウトソーシング。東海4県対応
- **正社員15名で派遣スタッフ約250名・累計登録者2万人超**を運営
- 想定される業務課題：求人案件とマッチング進捗の管理、企業（派遣先）との商談履歴、登録スタッフのフォロー記録、派遣法関連のコンプライアンス書類・手続きナレッジ

### グループとしての特徴
- 両社は代表者が同一（長谷川裕一氏）のグループ会社で、本社も同じビル（オリックス名古屋錦ビル9階）
- **美建の現場人材ニーズと日美の人材供給機能を連携させる情報基盤**が作れれば、グループシナジーが最も大きい

## 4. 御社への具体的提案

### 4-1. 株式会社美建向け

**① 物件（現場）管理データベース** — 最優先
- 担当物件ごとに1ページ：契約内容、作業仕様（清掃頻度・警備体制・点検周期）、担当スタッフ、緊急連絡先、図面・鍵情報の所在
- トラブル・クレーム対応履歴を物件ページに時系列で蓄積（不動産管理会社の事例と同型）
- 現場からスマホで写真付き報告 → 本社での報告書転記作業を削減

**② 法定点検・特別清掃のスケジュールと証跡管理**
- 受変電設備点検、貯水槽清掃、消防設備点検などをカレンダービューで一覧化し、期限アラートを設定
- 実施記録・報告書PDFを物件ページに紐付け、監査・顧客照会時に即検索

**③ 有資格者管理**
- スタッフの資格（電気主任技術者、ボイラー技士、警備員検定等）と更新期限をDB化し、物件への配置要件と突合

**④ 業務マニュアル・安全教育Wiki**
- 清掃手順、警備対応フロー、事故時の連絡手順、新人教育資料を職種別に整備（石井建装の「お助け掲示板」方式）
- 190名の清掃スタッフの入替時も、教育の質を均一化

**⑤ 補修工事の案件パイプライン管理**
- 相談→見積→受注→施工→アフターをカンバンビューで管理。施工前後の写真をギャラリー化し、次の営業提案資料に転用

### 4-2. 日美株式会社向け

**① 求人案件・マッチング進捗管理** — 最優先
- 企業からの求人依頼を案件DB化：職種、条件、提案中の候補者、ステージ（依頼受付→人選→顔合わせ→就業開始）をボードビューで可視化（asken社の営業管理内製と同型）

**② 派遣先企業CRM**
- 企業ごとの商談履歴、契約条件、更新時期、担当者情報を一元化。15名の少人数組織での引き継ぎ・属人化リスクを低減

**③ コンプライアンス・労務手続きWiki**
- 派遣法関連の手続き、社会保険・産休育休等の対応フロー、よくある問い合わせへの回答集を整備。問い合わせ対応時間を削減（Figmaのサポート回答DB方式）

**④ 派遣スタッフのフォロー記録**
- 約250名の就業中スタッフの定期面談記録・相談履歴・契約更新状況を管理

> **注意**：登録者2万人の名簿全体や、勤怠・給与計算・派遣元管理台帳などの**法定帳簿はNotionに載せるべきではありません**（後述の「Notionに向かない業務」参照）。Notionが担うのは案件管理・商談履歴・ナレッジの層です。

### 4-3. グループ共通

**① グループ全社Wiki**
- 会社規程、稟議・承認フロー、議事録、経営会議資料を一元化。トヨタの承認フロー改善・大阪ガスの議事録運用と同型
- 同じビル内の2社なので、共通ワークスペース＋会社別の権限設定（チームスペース）で運用可能

**② 採用管理（ATS）の共通化**
- 美建の現場スタッフ採用・日美の登録者募集の選考管理をNotionフォーム＋候補者DBで構築（サブリメイション・ブライエッジの事例と同型）
- 新入社員オンボーディングのチェックリスト化（LayerX方式）で、入社直後の離職を抑制

**③ グループ間の人材連携ボード**
- 美建の現場人員ニーズ（欠員・繁忙）と日美の候補者情報をつなぐ共有ボード。グループならではのシナジーで、他社には作れない情報基盤になる

**④ Notion AIの活用（Businessプラン以降）**
- 議事録の自動要約、マニュアルの横断検索（「貯水槽清掃の手順は？」と聞けば答えが返る社内チャットボット的な使い方）、報告書の下書き生成

## 6. 成功のポイントと注意点

### 失敗パターン（先行企業の教訓）
1. データベースの「箱」だけ作って更新ルール・責任者が不在 → 放置される
2. 現場の実際の業務フローと合わない設計 → 使われない
3. 既存のExcel・紙と並存させてしまい、情報の置き場所が増えただけになる
4. 経営層と現場で導入目的の認識がズレる

### 成功のコツ
1. **目的を1つに絞って開始**（例：「物件情報を探す時間をゼロにする」）
2. **更新の責任者と頻度をルール化**し、気合いに頼らない
3. 公式・無料テンプレート（施工管理・日報・CRM等）を複製してカスタマイズ
4. 協力会社・職人との共有が始まったら、権限管理の観点で早めにBusinessプランへ
5. 見た目を整える（ダッシュボード1枚から）ことが定着率に直結

### Notionに向かない業務（専用システム推奨）
- **勤怠・給与計算・シフト作成**：清掃190名のシフトは専用SaaS（勤怠管理システム）が適切
- **派遣元管理台帳などの法定帳簿**：派遣業向け基幹システムで管理し、Notionには運用ナレッジのみ
- **登録者2万人規模の名簿データベース**：個人情報保護とDB性能の両面から専用ATS/派遣管理システムが適切
- Notionは「基幹システムの置き換え」ではなく「**紙・Excel・口頭に散らばった業務ナレッジと案件情報の一元化**」に使うのが正解です
