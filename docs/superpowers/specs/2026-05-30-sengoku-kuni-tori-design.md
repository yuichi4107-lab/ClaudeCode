# 戦国・国盗り戦略ゲーム 設計書

- 作成日: 2026-05-30
- ステータス: 設計合意済み（実装計画づくりへ）
- 形式: ブラウザ（素のHTML/CSS/JS・ビルドレス・ESモジュール）

## 1. 概要とゴール

戦国時代を舞台に、プレイヤーが一大名となり、内政・外交・合戦を通じて領土を拡大し
**全国統一**を目指すブラウザ版の国盗り戦略シミュレーション（信長の野望系）。

**今回のゴール**: フルマップ（60超の旧国）上で「開始 → 拡張 → 統一」まで
**一通り遊べる完成ループ**を、各システムを軽量（合戦は自動解決）に保って実装する。
深掘り要素（戦術合戦・婚姻外交・複数シナリオ・史実イベント等）は後から積み増せる
構造を保つ。

## 2. スコープ

### やること（プロトタイプ完成ループ）
- 60超の旧国を持つフルマップ（ノード地図表現）
- 1560年（桶狭間直前）シナリオの史実大名版図・能力値
- 季節制ターン（春夏秋冬＝年4ターン）
- 内政コマンド（開発／徴兵／訓練）
- 大名行動（出陣＝隣接敵国への攻撃、外交＝同盟提案）
- 合戦の自動解決
- 全AI大名の意思決定（開発・徴兵・攻撃・同盟）
- 全国統一による勝利／プレイヤー消滅による敗北
- セーブ／ロード（localStorage）

### やらないこと（将来拡張）
- 戦術合戦（マス目・采配コマンド）→ 今回は自動解決のみ
- 婚姻・人質・従属など高度な外交
- 史実個別イベント（桶狭間・川中島など）の再現スクリプト
- 複数シナリオ年・架空シナリオ
- 日本地図シルエットSVG（ノード地図で代替、後段で差し替え可能な設計に）
- 武将個人（家臣）の管理 → 今回は大名1人の能力値に集約
- 音楽・効果音

## 4. アーキテクチャ

### 方針
素のHTML/CSS/JS、ビルドなし、ESモジュール（`<script type="module">`）。
依存ゼロでブラウザから直接動作。ゲーム本体はビルドレスを維持し、テストのみ
開発依存（Vitest）を使う。

### ディレクトリ／モジュール構成
```
sengoku-game/
├── index.html            # エントリ・キャンバス/パネルのDOM骨格
├── styles.css            # スタイル
├── src/
│   ├── main.js           # 初期化・ターンループ統括・イベント配線
│   ├── data/
│   │   ├── provinces.js  # 60超の国（旧国名・地方・隣接・石高・地形）
│   │   └── daimyo.js     # 1560年シナリオの大名（家名・色・本拠・能力・初期版図）
│   ├── engine/
│   │   ├── state.js      # ゲーム状態の生成・初期化・参照ヘルパ・セーブ/ロード
│   │   ├── economy.js    # 収入・維持・民忠（純粋関数）
│   │   ├── combat.js     # 合戦自動解決（純粋関数）
│   │   ├── diplomacy.js  # 同盟の成立判定・管理（純粋関数）
│   │   └── victory.js    # 勝敗判定（純粋関数）
│   ├── ai/
│   │   └── ai.js         # AI大名の意思決定（純粋関数: state→行動リスト）
│   └── ui/
│       ├── render.js     # 地図・パネル・ログの描画
│       └── input.js      # クリック/コマンド入力→ゲームアクション変換
└── tests/                # Vitest（engine/ai の純粋ロジック）
    ├── economy.test.js
    ├── combat.test.js
    ├── diplomacy.test.js
    ├── victory.test.js
    └── ai.test.js
```

### レイヤと依存方向
- `data/` … 静的データのみ（依存なし）
- `engine/`・`ai/` … `data` と `state` に依存。**DOM非依存の純粋ロジック**（テスト対象）
- `ui/` … `engine`/`state` を読み、DOMへ描画。ロジックを持たない
- `main.js` … 全体を配線。ターン進行の順序を司る

**重要原則**: ゲームの計算ロジック（収入・合戦・AI・勝敗）は一切DOMに触れない
純粋関数とし、`(state, args) → 新しい結果/イベント` の形にする。これにより
ユニットテスト可能・AIとプレイヤーで同一ロジックを共有できる。

## 5. データモデル

### Province（国）
```js
{
  id: "owari",            // 一意ID（ローマ字）
  name: "尾張",            // 旧国名
  region: "東海",          // 地方（描画クラスタ用）
  x: 0.62, y: 0.55,       // ノード地図の正規化座標(0〜1)
  neighbors: ["mino","mikawa","ise","ile_kita"], // 隣接国ID
  terrain: "plain",       // plain/mountain/coast など（防御補正）
  baseKokudaka: 57,       // 基礎石高（万石、収入の基礎）
  // 以下は動的状態（初期値はシナリオで上書き）
  owner: "oda",           // 所有大名ID
  agri: 30,               // 農業開発度（兵糧産出）
  commerce: 30,           // 商業開発度（金産出）
  troops: 3000,           // 駐留兵力
  castle: 20,             // 城防御度（守備補正）
  loyalty: 70,            // 民忠（0〜100、低いと一揆/離反リスク）
  rations: 5000           // 兵糧備蓄
}
```

### Daimyo（大名）
```js
{
  id: "oda",
  name: "織田信長",
  family: "織田家",
  color: "#d23",          // 地図色
  isPlayer: false,        // プレイヤー操作か
  capital: "owari",       // 本拠国ID（陥落しても他国が残れば移転、全国喪失で滅亡）
  stats: { valor: 87, politics: 78, intellect: 90 }, // 武勇/政治/知略
  gold: 2000,             // 軍資金（金）
  alive: true,
  aiPersonality: "aggressive" // aggressive/balanced/defensive（AI性格）
}
```

### GameState
```js
{
  year: 1560, season: 0,    // season: 0春 1夏 2秋 3冬
  provinces: { [id]: Province },
  daimyo: { [id]: Daimyo },
  alliances: [ ["oda","tokugawa"], ... ], // 同盟ペア
  playerId: "oda",
  log: [ { turn, type, text } ],          // イベントログ
  status: "playing"        // playing/won/lost
}
```

## 6. コアループ（1季節）

`main.js` が以下の順で1ターンを進める。プレイヤー命令だけ対話的、それ以外は自動。

1. **収入/維持フェーズ**（全国）— `economy.js`
   - 金収入 = Σ(国ごと: `baseKokudaka × commerce係数 × 民忠係数`)
   - 兵糧収入 = Σ(国ごと: `baseKokudaka × agri係数 × 季節係数`)（秋は収穫増）
   - 維持費: 兵力に応じ兵糧消費、不足分は民忠低下＆兵力微減（飢餓）
   - 民忠の自然回復/低下
2. **プレイヤー命令フェーズ** — `input.js`
   - 各所有国に最大1つの内政コマンド（開発/徴兵/訓練）を割当
   - 大名行動: 出陣（隣接敵国を対象）／外交（他大名へ同盟提案）
   - 「ターン終了」で確定
3. **AI行動フェーズ** — `ai.js`
   - 各AI大名が `decideActions(state, daimyoId)` で行動リストを生成し適用
4. **合戦解決フェーズ** — `combat.js`
   - 発生した全攻撃を解決（攻守の損耗・国の奪取）
5. **判定フェーズ** — `victory.js`
   - 大名の滅亡処理（保有国0）。本拠陥落でも他国が残れば本拠移転
   - 勝利（playerが全国保有）／敗北（playerが消滅）を判定
6. 季節を進める（冬の次は翌年春）。`status==="playing"` なら1へ。

## 7. 主要ロジックの式

### 7.1 経済（economy.js）
- 商業収入(国) = `round(baseKokudaka × (commerce/100) × (0.5 + loyalty/200) × G)`
  - `G` は金係数（バランス調整定数、初期 8）
- 兵糧収入(国) = `round(baseKokudaka × (agri/100) × seasonFactor × R)`
  - `seasonFactor`: 春1.0/夏1.0/秋2.0/冬0.5、`R` は兵糧係数（初期 30）
- 兵糧維持 = `troops × 0.5`（季節あたり）。備蓄＋収入で賄えない分は
  `不足兵糧 / 0.5` 相当の兵力が餓死、民忠 −5
- 民忠: 何もしなければ毎季 +2（上限100）、徴兵直後は −、過密兵力で −

### 7.2 内政コマンド
- 開発（農業 or 商業）: 対象開発度 +`round(5 + politics/20)`（上限100）、金消費 100
- 徴兵: 金消費 200 → 兵力 +`round(800 + politics×4)`、民忠 −8
  （兵糧備蓄に上限を設け、過剰動員を抑制）
- 訓練: その国の兵の「精強度」を上げる簡易表現として、次回合戦時の
  士気補正を一時的に付与（実装: 国に `trained: true` フラグ→合戦後リセット）

### 7.3 合戦自動解決（combat.js）
入力: 攻撃側(大名・出撃元国・兵力)、防御側(国)。純粋関数で結果を返す。
```
attackPower  = atkTroops × (1 + atkValor/100) × trainBonusA × rand(0.85,1.15)
defensePower = defTroops × (1 + defValor/100) × terrainMul(defTerrain)
               × (1 + castle/100) × rand(0.85,1.15)
```
- `terrainMul`: plain 1.0 / coast 1.1 / mountain 1.3
- 比 `ratio = attackPower / defensePower`
- 損耗: 敗者は兵力の `40〜70%` を失い、勝者も `ratio` に応じ損耗
- 判定:
  - `ratio ≥ 1` かつ防御兵力が閾値未満 → **攻撃側が国を奪取**
    （残存攻撃兵力の一部を駐留として配置、所有者変更）
  - それ以外 → 攻撃失敗（両者損耗のみ）
- `rand` はテスト容易化のため**注入可能な乱数源**（既定 `Math.random`、
  テストは固定シードに差し替え）

### 7.4 外交（diplomacy.js）
- 同盟提案: 受け手AIが `相手勢力との国力比` と `aiPersonality` で受諾判定
  - 自分より強い相手／隣接で脅威 → 受諾しやすい
- 同盟中は相互不可侵（出陣不可）。一定確率/国力逆転で破棄あり（簡易）

### 7.5 勝敗（victory.js）
- 大名の滅亡: **保有国数が0になったとき**（`alive=false`）。
  本拠が陥落しても他国が残る場合は滅亡せず、本拠を残存国へ移転する。
- 勝利: `playerの保有国数 === 総国数`
- 敗北: `player.alive === false`（全国喪失）
- ゲーム継続中も各大名の滅亡（版図0）を逐次処理

## 8. AI設計（ai.js）

`decideActions(state, daimyoId, rng) → Action[]`（純粋関数）。性格別に重み付け:
- **aggressive**: 最弱の隣接敵国へ積極出陣。徴兵優先
- **balanced**: 国力に余裕があれば出陣、なければ開発/徴兵
- **defensive**: 開発・城強化中心、攻められたら反撃のみ

評価の骨子:
1. 収支が苦しければ商業開発
2. 兵糧が薄ければ農業開発
3. 兵力と金が十分かつ隣に勝てそうな敵国があれば出陣（勝率推定 = 自軍推定攻撃力 / 敵守備力）
4. 強大な隣接勢力には同盟提案
全AIが**プレイヤーと同じengineロジック**で行動するため、挙動が一貫する。

## 9. UI構成（render.js / input.js）

- **上部バー**: 年・季節／自勢力（金・総兵力・国数）／「ターン終了」ボタン
- **中央 マップ**: SVGノード地図。国＝円（所有者色）、隣接＝線。
  クリックで国選択。自国は操作可、敵国は出陣対象として選択可。
- **右 情報パネル**: 選択国の全ステータス＋実行可能コマンドボタン
- **下 ログ**: 合戦・奪取・同盟などのイベント時系列／簡易勢力ランキング
- **モーダル**: 合戦結果・勝敗・大名滅亡の通知

レンダリングは「state を受け取り全描画を再構築」する単純方式（差分描画はしない）。
60超ノードなら十分軽量。

## 11. 史実データ整備計画（最大の山場）

60超の旧国と1560年版図は精度が肝。実装計画では**専用工程**として扱う:
1. **国リスト編纂**: 旧国名・地方・基礎石高・地形・概略座標
2. **隣接関係**: 各国の隣接国（陸続き＋主要海路）を双方向で整合
3. **1560年版図**: 各国の所有大名を史実準拠で割当（主要大名の版図）
4. **大名ロスター**: 主要大名の家名・本拠・能力値（武勇/政治/知略）・色・性格
5. **相互検証**: 隣接の対称性（AがBの隣ならBもAの隣）、孤立国なし、
   全国がいずれかの大名 or 中立に属する、本拠が自領内、を機械チェック＋目視突合

> 注: 能力値・石高は「史実の雰囲気を出す簡略値」であり学術的厳密性は目標としない。
> 隣接・所属・本拠の**構造的整合性**はテストで保証する。

## 12. テスト方針

- **ユニットテスト（Vitest）**: `economy / combat / diplomacy / victory / ai` の純粋関数
  - 例: 合戦で攻撃側圧倒→奪取、拮抗→失敗、乱数固定で決定的に検証
  - 例: 収入計算が民忠/季節で増減する
  - 例: 勝敗判定が境界（残り1国）で正しい
- **データ整合テスト**: 隣接対称性・所属網羅・本拠妥当性（§11-5）
- **手動確認**: ブラウザでの1ゲーム通しプレイ（開始→数ターン→合戦→奪取→統一/敗北）
- TDD: エンジン純粋関数は「失敗するテスト→実装」の順で組み立てる

## 13. エラーハンドリング／エッジケース

- 兵糧/金が不足する命令は実行不可（UIで非活性＋理由表示）
- 同盟国への出陣は禁止
- 兵力0の国からは出陣不可
- 大名の最後の国が落ちたら滅亡処理（同盟・参照を掃除）
- ロードしたセーブのスキーマ不一致時は警告して新規開始
- 乱数源は注入式（テスト決定性のため）
