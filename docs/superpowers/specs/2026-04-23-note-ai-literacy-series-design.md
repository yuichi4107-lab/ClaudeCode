# note記事シリーズ「AIを使いこなす」5本 設計書

作成日: 2026-04-23
著者: YN Factory（ユーイチ）

## 1. ゴール

note で5記事連続公開し、以下を達成する。

- **ポジショニング確立**: 「AI=楽する道具」と見る層、および「AIを使っている」と自称する層の双方に対し、"本当に使いこなす"のは技術であると認識させる
- **リード獲得**: コンサル（スポット/顧問）・yntools・準備中の講座/コミュニティに繋がる興味層を集める
- **教育コンテンツの土台**: 今後立ち上げる講座・コミュニティの価値を先に言語化しておく

## 2. ターゲット読者

2つの読者層を意識して書き分ける（記事ごとに主たる読者を設定）。

- **B: 非エンジニアの副業／個人事業主** — "AI副業"的な煽り情報に触れ、手を出しては挫折しがち。「自分にもできるか？」の判断材料を探している
- **C: 経営者／マネージャー（小さな会社）** — AI導入を考えているが、組織や品質の観点で迷っている。"何から始めるべきか"のフレームを求めている

**意図的に避けること**：
- 「AIで事業を全部回しています」と誇示する表現
- 「誰でも簡単」「1時間で月◯万」系の煽り

## 3. トーン／スタンス

- 「AIは強力だが、使いこなすには技術（思考法＋設計力＋品質判断）が要る」を一貫して貫く
- 事業事例（yntools、AI投資、SNS自動化、ばんえい予想 等）は"方法論の裏付け"として使う。主語は「やり方」であって「俺の実績」ではない
- 読後に「学びたい／相談したい」と自然に思わせる。売り込みは最終記事に寄せる

## 4. 5記事の構成

### Article 1（入口・B/C共通）
**タイトル**: 「AIで楽してる」と言われる人の9割は、AIの1割も引き出せていない

- **役割**: 偏見の破壊＋自称AI使いへの揺さぶり
- **核となる主張**: 「AIで楽している」と見られる人の大半は、実はAIの能力のごく一部しか引き出していない。真に使いこなしている人は、むしろ楽をしていない（設計・品質確認・再設計に時間を使う）
- **骨子**:
  1. 「AIで楽してる」批判の構造（観測者バイアス）
  2. "使っている"と"引き出せている"は別次元である証拠（具体的な対比例）
  3. 真に使いこなす人が時間を使っているのは「タスク設計」「境界線」「品質評価」
  4. だから、批判も自称も的外れ。学べば登れる階段がある → #2以降へ
- **CTA**: 次記事予告（軽いリード）

### Article 2（段階1・B寄り）
**タイトル**: AIに仕事をさせる前に、必ず考える3つのこと

- **役割**: 読者が「明日から意識できる思考フレーム」を獲得
- **核となる主張**: プロンプトの書き方より、タスク設計の上流3問（目的／判断権限／成果の評価軸）を先に決めることが成功率を決める
- **骨子**:
  1. AI活用で失敗する人は、"投げ方"でなく"考え方"で失敗している
  2. 3つの問い: ①このタスクの目的は何か ②どこまでAIに決めさせるか ③何をもって合格とするか
  3. 具体例（日常業務での適用パターン）
  4. この3問を習慣化するだけで、AI活用の歩留まりが変わる

### Article 3（段階2・B寄り）
**タイトル**: プロンプトじゃない、AIを使うのに本当に必要な「境界線設計」

- **役割**: 実務スキルの核（何を任せ、何を任せないか）を明示
- **核となる主張**: プロンプト工学より「境界線設計」が上位スキル。AIに何を任せ／何を人間が握るかを切り分ける力が、事故を防ぎ成果を伸ばす
- **骨子**:
  1. プロンプト本を読んでも成果が出ない理由
  2. 境界線設計とは何か（判断の責任／一次情報の扱い／品質の最終承認）
  3. 自分の事業での境界線設計の実例（事業名は出しても、方法論として語る）
  4. 境界線が曖昧だと何が壊れるか（事故事例の抽象化）

### Article 4（段階3・C向け）
**タイトル**: AI社員を雇うな、AI部署を作れ — 小さな会社のAI組織論

- **役割**: 経営者視点で「組織として」AIを運用する設計論
- **核となる主張**: AIを"便利な新人"として個別に使うと破綻する。役割ごとのエージェント＋品質レビュー＋引き継ぎの"部署"設計が要る
- **骨子**:
  1. 「AI社員」比喩の限界（個人技依存、属人化、品質のブレ）
  2. 小さな組織でも機能する"AI部署"の最小構成: 要件定義／実行／品質チェックの3役
  3. 経営者が手放してよい判断、手放してはいけない判断
  4. 組織設計を一度作れば、人もAIも乗り換えられる

### Article 5（出口＋CTA・B/C共通）
**タイトル**: AIを使いこなせる人・組織が手にする5年後

- **役割**: ここまでの4本を踏まえ、「学び続ける側に回る」提案＋CTA
- **核となる主張**: AIは今後5年で"使える前提"の道具になる。差がつくのは「設計する側」に回れるかどうか。今から学べば間に合う
- **骨子**:
  1. AIの日常化は不可逆。"使える前提"の時代に必要なのは差別化スキル
  2. 使いこなせる人／組織の5年後シナリオ（具体的な仕事/組織の変化）
  3. 学ぶ手段: 自走／伴走（コンサル）／ツールで試す（yntools）／仲間と学ぶ（準備中のコミュニティ・講座）
  4. CTA: コンサル案内、yntools案内、講座・コミュニティの先行案内リスト登録

## 7. 品質基準（quality-checker で採点）

1. **メッセージ整合性（20点）**: 「AIを使いこなすには技術が要る／学べば登れる」の軸がブレていない
2. **ポジショニング（15点）**: 「AIで楽している」表現を使わず、AI活用の価値と難しさを両立させている
3. **読者への刺さり（20点）**: 指定ターゲット（B/C）に刺さる具体例・表現になっている
4. **構造と流れ（15点）**: 導入→主張→根拠→行動提案の構造が守られている
5. **具体性（15点）**: 抽象論だけでなく、事業事例または読者の日常に接続する具体例が含まれている
6. **CTA設計（10点）**: 各記事の役割に応じたCTA強度になっている（#1-4は軽め、#5は本番）
7. **文体・読みやすさ（5点）**: note読者が最後まで読める文章密度と改行

合格ライン: **85点以上**
