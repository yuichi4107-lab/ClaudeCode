# 会社案内マンガ（10P）シナリオフォーマット【無料版・公開情報ベース】

会社案内・サービス紹介マンガ（8〜16P、標準10P）のシナリオを、誰が書いても一定の品質になるように型化したテンプレート。
モデルケース: YNファクトリー（電子書籍出版プロデュース） https://www.ynfactory.online/

## 運用前提（無料版）

- **クライアントへのヒアリングは行わない。** HP・ブログ・SNSなどの公開情報のみを材料に、こちらの判断で作り切る
- タイトル・CTA・ターゲット・シナリオはすべて**こちらで勝手に決めてよい**（後述の判断ルールに従う）
- 完成品は「たたき台（提案用ドラフト）」として先方に渡す想定。事実誤認があれば先方修正で直せる品質で出す

### 勝手に作るときの鉄則

1. **会社の事実（社名・サービス・住所・連絡先・実績数値）は公開情報にあるものだけ**を使う。数字・実績・お客様の声を創作しない
2. 理念・想いは**サイトに書いてある言葉をなるべくそのまま**使う（勝手な言い換えで思想がズレるのが一番のクレーム要因）
3. 主人公・ストーリーはフィクションでよい。ただし「その会社の典型顧客ならありそう」な範囲に収める
4. 公開情報に無くて埋まらない項目は、創作せず**空欄のまま「要確認」と明記**する（例: 料金、実績件数）

---

## 使い方

1. 「STEP 0 公開情報リサーチシート」で材料を集める（30〜60分で切り上げる）
2. 「STEP 1 前提設定シート」を判断ルールに従ってこちらで決めて埋める
3. 「STEP 2 10ページ構成表」に沿って各ページの役割を確認する
4. 「STEP 3 ページ別シナリオシート」をページごとにコピーして埋める
5. セリフは1コマ30字以内 × 最大2吹き出しを目安にする（マンガは「読ませない」が正義）

## STEP 1: 前提設定シート（こちらで決める）

| 項目 | 記入欄 | 【判断ルール】迷ったらこう決める |
|---|---|---|
| 作品タイトル | | サイトのキャッチコピーを疑問形・呼びかけ形に変換する（例: 「最強の名刺になる」→「最強の名刺、つくりませんか？」） |
| 目的（ゴール行動＝CTA） | | **無料版はQRコード・専用リンクを作らない。** HPに記載のメールアドレス・電話番号をそのまま文字で載せる。両方あればメール優先＋電話併記 |
| ターゲット読者 | | サイトが語りかけている相手をそのまま採用し、年齢・職業を1人に絞って具体化する |
| 読後に抱いてほしい感情 | | 原則固定: 「これ私のことだ。話だけでも聞いてみたい」 |
| 掲載媒体 | | 不明なら「LP埋め込み・縦スクロール」想定で作る |

### 登場キャラクター（フィクションで作ってよい）

**主人公（＝ターゲット読者の分身）**

| 項目 | 記入欄 | 【判断ルール】 |
|---|---|---|
| 名前・年齢・職業 | | ターゲット読者をそのまま人物化。名前はありふれた姓名に |
| 現状の悩み（表面） | | そのサービスを検索する直前に起きていそうな出来事 |
| 本当の悩み（深層） | | サイトのコンセプトが「答え」になるように逆算して設定する |
| 悩みが解決した後の姿 | | サービス利用後に起こる変化。数字を創作しない範囲で描く |

**ナビゲーター（＝会社側のキャラ）**

| 項目 | 記入欄 | 【判断ルール】 |

## STEP 2: 10ページ構成表（黄金パターン）

「共感 → 出会い → 納得 → 安心 → 行動」の流れ。ページ役割は原則入れ替えない。

| P | 役割 | 読者の感情の動き | 内容 |
|---|---|---|---|
| 1 | フック（悩みの提示） | 「あ、これ私だ」 | 主人公が悩んでいる日常シーン。タイトルもここに |
| 2 | 共感（悩みの深掘り） | 「そうそう、それで困ってる」 | 悩みの「あるある」を具体的に3つ程度見せる |
| 3 | 転機（出会い） | 「ん、何それ？」 | 会社・サービスとの接点。知人の紹介、SNS、検索など自然な出会い方で |
| 4 | 登場（会社紹介） | 「ちゃんとした会社なんだ」 | ナビゲーター登場。会社名と「何をしてくれる会社か」を一言で |
| 5 | 理念（なぜやるのか） | 「想いに共感できる」 | コンセプトをサイトの言葉で語る。ここは売り込まない |
| 6 | 解決①（主力サービス） | 「そんなことができるのか」 | 主力サービスの内容を、主人公の悩みに対する答えとして見せる |
| 7 | 解決②（サービス全体像） | 「ここまでやってくれるんだ」 | サービス②③を紹介。図解コマ（マンガ内インフォグラフィック）が有効 |
| 8 | 安心（利用の流れ） | 「これなら私にもできそう」 | 相談〜納品のステップを3〜4コマで。料金は公開されている場合のみ |
| 9 | 証拠（変化・実績） | 「本当に変われるんだ」 | 主人公のビフォーアフター。公開実績があれば添える（創作禁止） |
| 10 | 行動（まとめ・CTA） | 「話だけでも聞いてみよう」 | 決めゼリフ→CTA→会社情報。CTAコマはHP記載のメールアドレス・電話番号の文字表記のみ（QRコード不使用）。行動のハードルを下げる一言を添える |

## 執筆ルール（チェックリスト）

- [ ] 会社の事実はすべてSTEP 0の転記欄（出典あり）から引いている。創作した数字・実績・声がない
- [ ] コンセプト・決めゼリフはサイトの原文ママ
- [ ] 実在の代表者・スタッフを無断でキャラ化していない
- [ ] セリフは1吹き出し30字以内。説明したくなったらナレーションかコマ分割
- [ ] P1〜P3に会社名・サービス名を出さない（先に共感、売り込みは後）
- [ ] サービス説明は「機能」でなく「主人公の悩みがどう解決するか」で書く
- [ ] P10のCTAは1つに絞る。連絡先は公開情報から正確に転記する
- [ ] 埋まらなかった項目は「要確認」と明記して残してある（納品時に先方が直せる）
- [ ] 読み終わりまで3分以内を想定（総コマ数45〜55コマ目安）
