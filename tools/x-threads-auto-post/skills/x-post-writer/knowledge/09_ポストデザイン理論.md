# ポストデザイン理論

## 目的
**ポストは文字ではなく「デザイン」。文字盤を避け、視覚的に読みやすくせよ。**

---

## 【根本思想】

### ポスト = デザイン

**❌ 間違った考え方:**
- ポスト = 文字を書くこと
- 3000字書けばいい
- 内容さえ良ければ読まれる

**✅ 正しい考え方:**
- ポスト = デザイン
- 文字の配置・リズム・視覚的な変化を設計する
- 内容が良くても、デザインが悪いと読まれない

---

## 【人間の集中力は続かない】

### 文字盤の問題

**文字だけの長文:**
```
ああああああああああああああああああああああああああああ
ああああああああああああああああああああああああああああ
ああああああああああああああああああああああああああああ
ああああああああああああああああああああああああああああ
ああああああああああああああああああああああああああああ
```

**読者の反応:**
- 「うわ、長い...」
- スクロールして飛ばす
- 離脱する

---

### デザインされたポスト

**文字 + 箇条書き + フローチャート:**
```
ああああああああああああああああああああああああああああ

・箇条書き1
・箇条書き2
・箇条書き3

ああああああああああああああああああああああああああああ

フローチャート
↓
フローチャート
↓
フローチャート

ああああああああああああああああああああああああああああ
```

**読者の反応:**
- 「お、変化がある」
- スクロールを止める
- 視覚的に理解しやすい
- 最後まで読む

---

## 【デザインの3要素】

### 1. 文字（長文）

**役割:**
- 説明、ストーリー、感情の深掘り

**使い方:**
- 1ブロック = 50-100字程度
- 長すぎる場合は改行で分割

**例:**
```
私も昔は勘違いしてたからわかる。

「コピーライティング完璧にマスターして売ろう」と決意して、本を5冊買って、意味不明だが一応読んで...
（×長すぎ、改行なし）

↓デザインする

私も昔は勘違いしてたからわかる。

（ここでフローチャート形式に切り替える）
```

---

### 2. 箇条書き

**役割:**
- 情報の整理
- 視覚的なアクセント
- スクロールを止める

**使い方:**
- 3-5個程度
- 各項目は1-2行

**例:**
```
スキルゼロでも売ってる人が勝つ理由

・データが取れる→「どこで離脱したか」全部わかる
・改善サイクルが速い→スキル磨き6ヶ月 vs 売って翌日改善
・失敗＝改善ポイント→売ってない人は「才能がない」と凹む
```

**効果:**
- 視覚的に整理されてる
- 読みやすい
- 情報量が多いのにスッキリ

---

### 3. フローチャート形式（「↓」）

**役割:**
- 時系列の可視化
- 自己投影の強制
- スクロールを止める力が最強

**使い方:**
- 失敗談
- 成功体験
- よくある失敗パターン
- 5-10ステップ程度

**例:**
```
「コピーライティング完璧にマスターして売ろう」と決意
↓
誰が読むんこれwwwって分厚い本5冊買う
↓
意味不明だが一応読む
↓
「よし！これで行ったれ！」でLP書くも、自分で読み直して「違くね？w」でボツ
↓
また本読む
↓
また書く
↓
またボツ
↓
エンドレスで3ヶ月経過
↓
売上？ゼロwww
```

**効果:**
- 視覚的に時系列が分かる
- 「これ俺だわ...」と自己投影
- 階段を降りる感覚で読み進める

## 【デザインの配置ルール】

### ルール1: 文字だけが3ブロック以上続いたらアウト

**❌ 悪い例（文字盤）:**
```
【ブロック1】文字だけ（100字）

【ブロック2】文字だけ（100字）

【ブロック3】文字だけ（100字）

【ブロック4】文字だけ（100字）
```
→ 読者が離脱

**✅ 良い例（デザイン）:**
```
【ブロック1】文字だけ（100字）

【ブロック2】文字だけ（100字）

【ブロック3】箇条書き（視覚的変化）

【ブロック4】文字だけ（100字）

【ブロック5】フローチャート形式（視覚的変化）
```
→ 読者が最後まで読む

---

### ルール2: 箇条書き・フローチャートは均等に配置

**❌ 悪い例（偏り）:**
```
序盤: 文字だけ
中盤: 文字だけ
終盤: 箇条書き + フローチャート連続
```
→ 序盤で離脱される

**✅ 良い例（均等配置）:**
```
序盤: 文字 + フローチャート（失敗談）
中盤: 文字 + 箇条書き（理由3つ）
終盤: 文字 + 箇条書き（方法3つ）
```
→ 最後まで読ませる

---

### ルール3: フローチャート形式は「失敗談」だけじゃない

**使えるシーン:**
- 失敗談
- **成功体験**（失敗だけじゃない！）
- よくある失敗パターン
- ビフォーアフター
- 選択肢分岐

**例: 成功体験をフローチャート化**
```
「もういいわ。とりあえず売ってみよ」って雑なレター（PDF）を5000円で出す
↓
初日で2人買った。1万円
↓
「は？こんな雑でも売れんの？」ってなる
↓
そこから毎日改善。見出し変える、価格変える、ターゲット変える
↓
1ヶ月後には月30万
↓
「お、いけるな」ってさらに改善
↓
3ヶ月後には月120万
```

## 【3000字長文の理想的なデザイン構成】

### 基本構造（14ブロック）

```
[1] フック（対比パターン）
    → 箇条書き形式（視覚的変化）

[2] 稼げない人のミス
    → フローチャート形式推奨（視覚的変化）

[3] これが正解
    → 箇条書き3つ（視覚的変化）

[4] 今のXアルゴ/市場環境説明
    → 文字（説明）

[5] よくある誤解
    → 文字（説明）

[6] 自分の失敗談
    → フローチャート形式必須（視覚的変化）

[7] テーマの魅力
    → 箇条書き3-5個（視覚的変化）

[8] 具体的な方法
    → 箇条書き3つ（視覚的変化）

[9] 失敗パターン回避
    → 文字（説明）

[10] 不安払拭
    → 文字（説明）

[11] CTA
    → 文字（誘導）

[12] 追加価値
    → 文字 or フローチャート（成功体験の場合）

[13] 最終警告
    → 文字（注意）

[14] 追撃CTA
    → 文字（誘導）
```

**視覚的変化の配置:**
- [1]: 箇条書き（対比）
- [2]: フローチャート推奨
- [3]: 箇条書き
- [6]: フローチャート必須
- [7]: 箇条書き
- [8]: 箇条書き
- [12]: フローチャート（成功体験の場合）

**合計:**
- 箇条書き: 4-5箇所
- フローチャート: 2-3箇所

→ 文字だけのブロックは最大3つまで連続しない
