# 実績CSV定義

## note_metrics.csv

| 列 | 定義 |
|---|---|
| date | 集計日 `YYYY-MM-DD` |
| run_id | note販売AIチームのrun ID |
| account_id | `accounts.json` のaccount ID |
| title | その集計日時点の公開記事タイトル。後日のタイトル変更は許容 |
| pv | その日1日に増えたPV（日次差分） |
| likes | その日1日に増えたスキ数（日次差分） |
| sales_count | その日1日の有料販売部数。無料記事は0 |
| revenue_yen | note管理画面等の正本から取得した、その日1日の対象記事売上金額（円）。同じCSV内では手数料控除前・控除後などの基準を統一 |
| price_yen | 販売価格。無料記事は0 |

有料転換率は、`price_yen > 0` の行だけを対象に `sales_count / pv` で計算する。無料記事のPVは分母に入れない。有料行がない、PVが0、必要値が `N/A`、または対象月に `price_yen=N/A` の行が1件でもある場合は転換率も `N/A`。

「売上あり / 売上なし」比較は有料期間のデータだけで行う。無料記事は別区分とし、価格または売上が不明な記事は不明区分に分ける。`price_yen=0` の行に売上部数または売上金額を入れない。売上部数と売上金額がともに既知なら、ゼロ・非ゼロが一致しなければ入力エラーとする。
一意キーは `date + run_id`。同一キーを2行入れない。
同じ `run_id` の日次行では `account_id` を固定する。タイトルは表示値なので変更でき、記事の不変IDとして使わない。

集計モードは `daily_delta` 固定。累計スナップショットを日ごとに並べない。CSVの前後空白は受け付けない。

## x_metrics.csv

| 列 | 定義 |
|---|---|
| date | 集計日 `YYYY-MM-DD` |
| run_id | 対応するnote run ID |
| variant | 採用した告知案ID |
| impressions | Xアナリティクスの表示回数 |
| engagements | エンゲージメント数 |
| link_clicks | noteリンクのクリック数 |

エンゲージメント率は `engagements / impressions`、クリック率は `link_clicks / impressions`。分母が0なら `N/A`。
一意キーは `date + run_id + variant`。同一キーを2行入れない。
実投稿数は日次行数ではなく、対象月内の一意な `run_id + variant` の組数とする。同じ投稿を複数日に観測しても1投稿として数える。

## 欠損値と出典

- 数値が取得できないセルは空欄ではなく `N/A`
- 数値は `0` 以上 `1000000000000000` 以下の半角整数
- 対象月の行が0件なら、件数は0、PV・売上・X合計は `N/A`
- `date` は実在する `YYYY-MM-DD`
- レポートに生成日時、入力CSV相対パス、SHA-256、全行数、対象行数を記録する

## 禁止

- 欠損値を平均や推測で埋めない
- 重複行を加算しない
- 公開画面から売上を逆算しない
- 異なる集計期間の値を同じ月次比較に混ぜない
