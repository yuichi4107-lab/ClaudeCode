# Weekly Sales Review — 週次営業レビュー

## 起動タイミング

- 毎週月曜 07:30 に `sales-briefing` スキルの末尾から自動的に「今週のレビューをしますか？」を提案（月曜のみ）
- オーナーが手動で `/weekly-sales-review` と打っても実行できる
- 月曜以外に実行しても動作する（中間確認用途）

## VPS 接続エイリアス

`~/.ssh/config` に以下を設定済み前提:
```
Host yn-vps
  HostName 163.44.101.31
  User root
  IdentityFile ~/.ssh/conoha_yn_factory
```

## ステップ

### 1. DASHBOARD_SALES.md からデータ読み込み

`.company/projects/AI導入支援営業/DASHBOARD_SALES.md` を Read して以下の数値を取得する:

- §1「現状スナップショット」: DM送信累計・今週送信数・返信数・返信率
- §1「ウェビナー」: 申込数・実施回数・次回開催予定日
- §1「商談・提案・成約」: Calendly予約数・商談実施数・提案書送付数・成約数・MRR
- §3「KGI進捗バー」: 各KGI の現在値・目標・進捗率
- §4「週次サマリー」: 直近4週分のトレンドデータ
- §5「KPI警告ライン」: 各警告の現状判定

### 2. VPS から最新の送信実績を補完取得（オプション）

DASHBOARD_SALES.md の送信数が「未更新」の場合は以下で最新データを取得する:

```bash
ssh yn-vps "cd /opt/sales-ops && ./venv/bin/python -c 'import os, json; from dotenv import load_dotenv; load_dotenv(); import sqlite3, datetime; since = (datetime.date.today() - datetime.timedelta(days=7)).isoformat(); conn = sqlite3.connect(os.environ[\"SALES_OPS_DB_PATH\"]); cur = conn.execute(\"SELECT COUNT(*) FROM approval_queue WHERE status=\\\"sent\\\" AND sent_at >= ?\", (since,)); print(json.dumps({\"sent_this_week\": cur.fetchone()[0]})); conn.close()'"
```

### 3. 先週の実績サマリーをオーナーに提示

以下のフォーマットで表示する:

```
=== 週次営業レビュー（YYYY-WXX / MM/DD〜MM/DD）===

【先週の実績】
  DM送信:      XX通  （目標: 5〜20通）
  返信数:      XX件  （返信率: X.X%）
  商談:        XX件  （Calendly予約: XX件）
  提案書送付:  XX件
  成約:        XX件  / MRR: XX,XXX円

【KGI進捗（2026-07-31まで残りXX日）】
  商談実施数:  X件 / 3件（X%）
  初契約:      0件 / 1件（0%）
  DM累計:      XX件 / 100件（X%）
  ウェビナー:  0回 / 1回（次回開催日まで残りXX日 ※開催日未確定の場合は「開催日が未設定です。今週中に確定してください」と表示）

【警告検知】
  ※ 発火した警告のみ表示（次セクションで詳述）
```

### 4. 停滞検知と警告発火（強制力仕掛け 1）

**以下の条件を上から順にチェックし、該当する警告をすべて出力する:**

```
警告A: 今週DM送信数 = 0
  → "本番DM送信がゼロです。DRY_RUN=false 切替が完了しているか確認してください。
     未完了の場合は LAUNCH_CHECKLIST.md §工程8b を今すぐ実行してください。"

警告B: DM返信率 < 1%（かつ2週連続）
  → "返信率が2週連続1%未満です。以下のアクションを検討してください：
     【具体策1】件名を変更する（現在の件名をここに表示）
     【具体策2】本文冒頭の「地方の中小企業の経営者」→「[業種名]の経営者」に絞る
     【具体策3】送信リストを税理士事務所・社労士事務所のどちらか1業種に絞って集中させる"

警告C: Calendly予約数 = 0（かつ今月）
  → "今月のCalendly予約がゼロです。以下を確認してください：
     1. Calendly公開URLをウェビナーLP・DM本文・SNSプロフィールに掲載済みか
     2. Calendly管理画面でURLが公開状態（Published）になっているか（LAUNCH_CHECKLIST.md §工程5b参照）"

警告D: 商談数 = 0（かつ今月）
  → "今月の商談実施がゼロです。ウェビナー参加者・既存接点へのCalendly個別案内を強化してください：
     - ウェビナー参加者全員にフォローDMを送る（booking-ops/follow-up-email-templates.md 参照）
     - SNS/noteの投稿末尾にCalendly URLを追記する"

警告E: 直前の週のDM送信・商談・提案がすべて0
  → "【停滞警告】先週はアクションがゼロでした。
     今週の必達アクション（1件）を今ここで決定します（次のステップへ進みます）"

警告F: ウェビナー開催予定日まで14日以内かつ未開催
  → "ウェビナーまで残りXX日です。Peatix告知・SNS投稿・DM内のウェビナー告知文の追加を今週中に完了させてください。"

警告G: ウェビナー開催予定日まで7日以内かつ申込者5名未満
  → "【緊急】ウェビナーまであとXX日。現在の申込者はX名（目標5名）です。
     今すぐできるアクション：
     1. 既存接点（LinkedIn/Facebook）に個別DM送信
     2. SNSに告知投稿（ウェビナー成果物パス: .company/projects/AI導入支援営業/ウェビナー/第1回-人手不足AI活用5選/）
     3. DM本文にウェビナー告知文を追加してこの週の送信で告知を兼ねる"
```

### 5. 今週の「必達アクション」を1〜3個確定（強制力仕掛け 2）

**前回確定した必達アクションの完了確認:**

前回の必達アクションを `.company/reviews/` 直近ファイルから読み込み、オーナーに完了確認を求める:

```
【前回の必達アクション（YYYY-WXX）】
  1. [前回のアクション内容] → 完了 / 未完了？

未完了のアクションは今週の必達リストに自動で引き継ぎます。
```

**今週の必達アクション確定:**

警告・KPI状況から推奨アクションを1〜3個提案し、オーナーの確定を得る:

```
【今週の必達アクション（提案）】
  優先1: [KPI最悪の指標から逆算した具体的アクション]
  優先2: [次点の指標への対応]
  優先3: [ウェビナー/商談KGI逆算から必要なアクション]

このまま確定しますか？修正がある場合は指示してください。
```

確定後、必達アクションは `DASHBOARD_SALES.md §6（アクション待ち一覧）` の「その他」行に登録する。

### 6. KPI未達時の具体的アクション提案

KPI未達の指標が1つ以上ある場合、以下のルールで具体的打ち手を提示する（精神論は絶対に書かない）:

| 未達KPI | 具体的アクション（例示） |
|---|---|
| DM返信率 < 1% | 件名のA/Bテスト（現行件名 vs 「[業種名]の採用難を解決した方法」型）|
| DM返信率 < 1%（2週連続） | 送信対象業種を1種類に絞る / 本文冒頭3行を変更する（NG例→OK例を提示） |
| DM送信 = 0 | DRY_RUN=falseへの切替手順（LAUNCH_CHECKLIST.md §工程8b）をオーナーに提示 |
| 送信数 < 5通 | 送信上限を5通 → 30通に増やす（`DAILY_SEND_LIMIT` 設定の変更箇所を提示） |
| Calendly予約 = 0 | Calendly URLをDM本文・ウェビナーLP・SNSプロフィールの3箇所に追加する |
| 商談 = 0 | ウェビナー参加者全員にフォローDM送信 / 既存接点への個別連絡 |
| 提案書送付 = 0 | 商談後即日、`booking-ops/proposal-auto-draft.md` を使って15分でドラフト生成 |
| 成約 = 0（提案3件以上） | フォローメールを再送（3〜7日後）/ クロージング理由のヒアリング商談を設定 |

### 7. KGI残日数・進捗の可視化（強制力仕掛け 3）

毎回必ず表示する:

```
=== KGI残り時間（本日: YYYY-MM-DD）===
  KGI期限（2026-07-31）まで: XX日
  ウェビナー次回開催日まで: XX日  ← 「次回開催予定日」が「未確定」の場合は「開催日が未設定です。今週中に確定してください」と表示して残日数計算は省略

【逆算チェック】
  商談3件ゴールまで残りX件 → 残りXX日で1件あたりXX日のペース
  DM累計100件ゴールまで残りXX件 → 残り週数でXX件/週が必要
```

このセクションは **残り30日以内になると毎回冒頭に大きく表示する**（平常時は末尾に表示）。

### 8. DASHBOARD_SALES.md を更新

以下のセクションを更新する（Editツール使用）:

1. `§1 現状スナップショット`（最終更新日 + 今週の実績値に上書き）
2. `§2 ファネル転換率テーブル`（実績転換率を再計算して更新）
3. `§3 KGI進捗バー`（現在値・進捗率・残日数を更新、テキスト進捗バー `█` を塗り埋める）
4. `§4 週次サマリー`（新行を末尾に追加し、4週超えは「週次トラッキング履歴」へ移動）
5. `§5 KPI警告ライン`（現状値・現状判定を更新）
6. `§6 アクション待ち一覧`（完了分削除・新規追加・必達アクション登録）

## sales-briefing との統合（月曜のみ）

`sales-briefing` スキルのステップ7完了後、以下を追記して月曜のみ週次レビューを促す:

```
（月曜の場合のみ表示）
---
今日は月曜日です。週次営業レビューを実施しますか？
[Y] はい → /weekly-sales-review を起動
[N] いいえ → このまま終了
```

オーナーが「Y」を選択したら `weekly-sales-review` スキルのステップ1から実行する。
