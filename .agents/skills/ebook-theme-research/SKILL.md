# 電子書籍テーマ調査スキル

日本の電子書籍市場（Kindle/KDP個人出版）で今後流行しそうなテーマを10個特定し、
根拠・ターゲット読者・参入タイミング付きの日本語レポートを作成する。

このスキルはどのモデルでも実行できるよう、判断基準と手順をすべて明文化してある。
WebSearch / WebFetch があれば動く。Agent ツールが使えるなら検索アングルごとに
並列サブエージェントを起動してよが、必須ではない（逐次検索でも可）。

## 背景知識1: バズ→書籍需要のタイムラグ（これを前提に「先回り」する）

| シグナル | 書籍需要化までのラグ | 含意 |
|---|---|---|
| TikTok/SNSで既刊がバズ | 数日〜数週間 | 事後即応のみ（Amazon急上昇で検知） |
| SNSバズ→重版級ヒット | 約3ヶ月 | 例: 『あの花が咲く丘で〜』7.5万部/3ヶ月 |
| Web記事バズ→書籍化 | 約9ヶ月 | 例: 『変な家』オモコロ記事→9ヶ月後刊行 |
| 検索トレンド予測→流行本格化 | 約1年 | 例: 「ラブブ」検索240倍→翌年大流行 |
| note発バズ→商業書籍化 | 6〜18ヶ月 | noteのバズは「1年後の書籍市場」の先行指標 |
| 米国市場ヒット→日本波及 | 12〜24ヶ月 | 例: Fourth Wing→邦訳16ヶ月遅れ |
| 制度変更（施行日確定） | 施行6〜12ヶ月前から需要形成 | 例: 新NISA本は施行前の年末年始がピーク |
| アニメ化・ドラマ化発表 | 発表→放送まで約半年（アニメ）/1〜3ヶ月（ドラマ） | 放送開始〜放送中が需要ピーク |
| 文学賞 | 候補発表が受賞の2〜3ヶ月前、効果は発表後30日 | 受賞で売上30〜120倍の実例あり |
| 資格試験 | 試験日の2〜4ヶ月前から参考書需要 | 日程は公表済みで予測可能 |

KDPは商業出版より制作リードタイムが半年〜1年短い。この差を使い、
「今バズり始めたシグナル」を商業出版が本を出す前に電子書籍化するのが基本戦略。

## 背景知識2: 監視すべき指標（SNS＋SNS以外）

**カレンダー型**（確度最高・毎年再現）: 文学賞日程（芥川・直木1月/7月、本屋大賞ノミネート1月・発表4月）、
税制改正大綱（12月）、確定申告（2-3月）、新生活（3-4月）、資格試験日程、
電子書籍の二大商戦期（12-1月と7-8月）、Kindle大型セール。

**発表型**（2〜6ヶ月の準備期間が取れる）: アニメ化・ドラマ化発表、文学賞候補発表、
法案成立・制度施行日の確定、新資格・新シラバス発表、米国ベストセラーの邦訳決定。

**ショック型**（事後即応・1〜3ヶ月で参入）: 技術シーク（新AIモデル等）、経済イベント（株価・為替の大変動）、
テレビでの書籍紹介（効果は24時間で消滅、同テーマへの回遊需要を拾う）、
テレビでの書籍紹介（効果は24時間で消滅、同テーマへの回遊需要を拾う）、

**市場の構造的前提**: 日本の電子書籍市場は約6,700億円でコミックが約88%を占めるが、
コミックはレッドオーシャン化・成長鈍化。KDP個人出版の主戦場は「文字もの」
（実用書・ビジネス・自己啓発・エッコラ）で、深い階層のニッチ×専門性×一次情報（自分の経験）が勝ち筋。

## 手順

### Step 1: 現在日付の確認

`date` コマンド等で今日の日付を確認し、検索クエリの年・季節文脈（次の商戦期・次の制度イベント）を決める。

### Step 2: 6アングルのウェブ検索（各アングル2〜4クエリ）

`{今年}` `{来年}` は実際の年に置換すること。

1. **市場統計・業界レポート**: 「日本 電子書籍市場 {今年} 市場規模 成長ジャンル インプレス総合研究所 出版科学研究所」
2. **KDP売れ筋の実態**: 「Kindle出版 売れ筋 ジャンル {今年} KDP 個人出版 稼げるテーマ」「Kindle Unlimited 人気カテゴリ {今年}」
3. **SNS→出版の波及事例（直近）**: 「TikTok売れ 書籍 {今年} ヒット」「BookTok 日本 話題 {今年}」「SNS発 書籍化 {今年}」
4. **現在進行形のバズ・検索トレンドの生成**: 「{今年} バズ トレンド 話題 キーワード Z世代」「ヤフー トレンド予測 {来年}」「日経クロストレンド 若者トレンド予測」「SHIBUYA109 lab トレンド予測」
5. **発表型イベントの直近情報**: 「アニメ化 決定 発表 {今年}」「ドラマ化 原作 {今年}」「本屋大賞 ノミネート」「税制改正 施行 {来年}」「法改正 {来年} 施行」
6. **海外市場の先行シグナル**: 「Amazon Kindle bestseller trends {今年}」「BookTok trends {今年}」「NYタイムズ ベストセラー ジャンル」

有望なソースは WebFetch で本文を読み、具体的な数字・固有名詞を拾う。
1つのソースの主張は可能な限り別ソースで裏取りし、裏取りできなかった数字はレポートに「参考値」と明記する。

### Step 3: テーマ候補の生成と絞り込み

検索結果から候補テーマを15〜20個列挙し、以下でスコアリングして10個に絞る:

- **需要の根拠**: 複数の独立シグナル（検索トレンド＋SNS＋業界レポート等）が一致しているか
- **タイムラグの位置**: 今参入して商戦期・需要ピークに間に合うか）「藌景知識1の表で判定）
- **競争環境**: 商業出版・既存KDP本が飽和していないか（飽和ジャンルは「深い階層のニッチ」に言い換えられる場合のみ採用）
- **個人出版での実現性**: 一次情報や公開情報で書けるか

### Step 4: ガードレール（必ず適用）

- **著作権**: 特定作品への便乗は「作品便乗」（考察本・ファンブック・作品名を冠した本）を提案しない。
  「題材・ジャンル便乗」（作品が関心を向けさせた題材の解説本、同ジャンルのオリジナル作品）のみ提案する。
  例: 『地面師たち』→×「地面師たち考察本」/○「不動産詐欺の手口と防衛策」
- **金融・投資テーマ**: 個別銘柄・商品の推奨は金商法（投資助言業）リスクがあるため、
  提案する場合は「制度解説＋臫分の実践記」のェぃに陔定し、リスクを注記する
- **医療・健康テーマ,�: 効能断定は薬機法リスク�体験談・公的情報ベースの形に陔定して注記する

### Step 5: レポート作成

以下のフォーマットで日本語レポート {YYYY-MM-DD}

## 市場環境サマリー（3行以内）

## 今回の注目シグナル（前回から新たに観測されたもの）

## 流行しそうなテーマ10選
各テーマ:
**N. テーマ名**
- 根拠: （シグナルと出典URL）
- ターゲット読者:
- 参入タイミング: （いつまでに出すべきか、どの需要ピークを狙うか）
- リスク注記: （該当する場合のみ: 著作権・規制・飽和）

## 監視カレンダー（今後1ヶ月の発表型・カレンダー型イベント）

## 出典一覧
```

### Step 6: レポートの保存と過去比較

1. `docs/ebook-theme-reports/{YYYY-MM-DD}.md` にレポートを保存する
2. 同ディレクトに過去レポートがあれば読み、「新規登場テーマ」「順位変動」「消えたテーマ」を
   レポートの「今回の注目シグナル」セクションに反映する
3. git リポジトリ内で実行している場合はコミットし、`claude/ebook-theme-reports` ブランチにプッシュする
   （`git fetch origin claude/ebook-theme-reports` で既存ブランチがあればそこに積み、無ければ作成する。
   プッシュできない環境ならスキップし、レポート全文をチャットに出力するだけでよい）
4. レポート全文を必ずチャットにも出力する（ファイル保存のみで終わらせない）
